# 多级缓存本机对照结果（2026-10-02）

## 测试目的

验证热点商铺读取从 `Redis + MySQL` 升级为 `Caffeine + Redis + MySQL` 后的性能变化。

## 环境与口径

- 机器：Intel Core i5-11300H（4 核 8 线程），15.8 GB 内存
- 系统：Windows 11 10.0.26200
- 运行时：Zulu OpenJDK 8u462、Spring Boot 2.3.12、JMeter 5.6.3
- 依赖：本机 MySQL、便携式 Redis 5.0.14.1
- 请求：`GET http://127.0.0.1:8081/shop/1`
- 负载：200 并发，10 秒升压，持续 60 秒；每组 3 轮
- 预热：每轮先删除 Redis 商铺缓存，再请求一次接口完成缓存预热
- QPS：`样本数 / (最后一次响应结束时间 - 第一次请求开始时间)`
- P95：将每轮全部 `elapsed` 排序后取 nearest-rank 95 百分位

## 汇总

| 指标 | Redis 基线（三轮平均） | 多级缓存（三轮平均） | 变化 |
|---|---:|---:|---:|
| QPS | 5,990.3 | 12,656.0 | +111.3% |
| 平均延迟 | 30.72 ms | 14.48 ms | -52.9% |
| P95 | 46.0 ms | 34.3 ms | -25.4% |
| 错误率 | 0% | 0% | 持平 |

该结果说明 Caffeine 对本机热点读取有明显收益，但不代表生产环境承诺。跨网络 Redis、不同硬件、
响应数据大小、GC 和日志级别都会改变绝对数值；对外表达应同时给出压测参数与环境。
